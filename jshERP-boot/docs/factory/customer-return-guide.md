# 客户退货申请与收货

入口：「销售管理 → 客户退货申请与收货」。替换原销售退货菜单，沿用原菜单授权；原单据及历史数据保留。刷新或重新登录加载菜单。

## 配置与操作

租户负责人点击「退货审批领导配置」，选择实际领导账号。可配置多位，任意一位批准即可。账号同时需要相应菜单才能进入；仓库复用「订单库存核查」岗位权限及原仓库访问权限。

1. 原订单销售人员点击「选择已发货订单申请退货」，选本人已统一出库的订单。
2. 按原出库产品、批号和明细填写本次退货量、退货原因。允许部分退货和多次申请；待审批、已批准待收货及已收货数量合计均不能超过各原出库明细数量。待审批也占用可退额度，防止多份申请重复占用。
3. 任意一位配置领导批准，仓库才能收货。领导可以填写原因退回；销售可填写原因撤销尚未收货的申请。退回或撤销释放可退额度，重新申请会重新审批。
4. 仓库核对实物与批准数量一致后，选择实际收货仓库并确认。每份申请一次收齐；实物数量不符时仓库退回，由销售按实际数量重新申请，不能直接改批准数量。不同实际收货仓库可分开申请。
5. 确认收货生成原库存「其它入库」单，编号 `KHTH{退货单ID}`，保留原产品和批号，按原出库库存成本回入。库存和退货状态在同一事务提交。
6. 收货后直接恢复可销售库存，不重新抽样质检，也不再次等待领导放行。库存销售资格标记为合格、已释放，说明明确记载「退货业务恢复销售资格，无新增检测」，不伪造新的质检报告。新订单可以正常预留并发货。

## 数量和记录

- 统一出库后申请才可退货，申请只能选择该订单实际出库明细。原出库数量和已收货库存流水不能直接修改、删除、反审核。
- 并发申请按最新已占用额度检查；重复确认收货只有一次成功。失败会回滚库存、状态及记录。
- 成品批次数量保护使用净出库量：累计出库减去已确认收货的本模块退货，不能超过原整批放行量。仅申请或批准退货不会增加库存、可售量或可再次出库额度。
- 页面保留申请、审批、退回、撤销、收货操作人、时间和说明。业务以原订单、原出库明细及原批号追溯。
- 退款、补发由销售和外部财务另行处理，本模块不生成退款、应收冲销或补发订单。收货仓库应确保本模块实物与记录一致。
- 本模块处理从新发货模块完成统一出库的订单；旧系统历史销售退货单不会自动转换成新申请。

## 部署和检查

先执行 `015_customer_returns.sql`，再部署后端及前端。本机执行前备份 `.quality-local/before-returns.sql`。迁移创建新表，仅执行一次。

运行 `tests/factory_shipping_workflow.py --returns` 使用临时产品、订单、领导及仓库账号检验申请额度、任意领导审批、实际收货、直接再次销售、批次净出库限制、并发提交、单据保护及租户隔离；测试结束清理临时数据并还原配置。可加 `--preview` 保留临时页面供人工检查，检查后按回车清理。
