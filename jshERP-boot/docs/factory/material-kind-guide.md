# 产品和原料分开管理

商品管理下的“产品信息”和“原料信息”使用独立列表及菜单权限，底层共用物料、条码、批次和库存记录。

- 产品信息用于销售订单、生产和产品质检标准。原料不会出现在销售及产品质检选择框；销售保存接口也会拒绝原料条码。
- 原料信息用于车间领补退料。产品不会出现在原料选项；领料接口也会拒绝产品条码。
- 从哪个入口新增，就创建对应类型。类型在创建后不能通过编辑或导入更改，避免已有单据和库存失去含义。
- 查询重置、复制新增、Excel导入和导出均保留当前入口的类型范围。商品类别仍可用于各自列表的进一步分类。
- 新增原料入口继承原产品维护菜单的角色授权及编辑、导出按钮，之后可在角色管理分别调整。

部署前备份数据库，执行 `020_material_kinds.sql` 一次，再更新后端和前端。旧物料默认按产品保留，已知模拟原料 `RAW-MOCK-A` 迁为原料；保留原编号、条码、库存和业务流水。历史库如有其他原料，需按档案核实后另做归类，不能从名称猜测。

原产品入口 URL 保持 `/material/material`，新增原料入口 `/material/raw_material`。退出重新登录加载菜单。
