# 车间领料、补料与退料使用说明

## 本次已接通

生产任务排班完成 → 主任开领料单 → 提交仓库 → 仓库核实后确认发料 → 原系统生成其他出库并扣库存。

补料继续关联同一生产任务、产品、工序及车间；退料关联已确认的原领料或补料单，由仓库收到实物后确认入库。

## 进入模块

重新登录刷新菜单，打开「生产管理 → 车间领补退料」。也可以在生产任务联系表选中已安排车间排班的任务，点击「领料 / 补料 / 退料」。联系表详情中会显示关联单据及处理进度。

主任账号沿用生产模块的「生产人员配置」中各车间主任设置；仓库确认权限沿用「订单库存核查」权限。实际仓库选择仍受原系统仓库权限控制。正式原料及库存尚需按工厂实际资料维护，不会把测试物料当作正式物料保留。

## 开领料单

1. 主任选择生产任务，点击「开领料单」。本人车间须已接单并完成排班，其他车间可以仍在待接单或待排班。
2. 选择该任务已安排的产品行、工序和车间。
3. 手动选择原料商品、仓库、批号和数量，可以添加多行原料。
4. 数量使用商品档案基本单位，支持吨、千克等不同单位；同一张单不同原料的数量不会混加。批次原料必须填写原批号，非批次原料留空批号。
5. 可点击「查询库存」，查看实物、订单已预留量及可用数量。查询不占用库存。
6. 保存草稿后，单选该单，点击「提交仓库」。保存和提交均不扣库存。

本阶段由主任手填原料需求，不自动套配方或BOM。本模块选择基本单位、非序列号、非多属性商品；序列号及多属性原料流程尚未接入。

## 仓库发料

仓库选择待确认单据，点击「仓库确认」，核对原料、仓库、批号、数量和实际交接情况后确认。系统在确认时重新检查库存：

- 不允许超出实物可用量，已被销售订单预留的库存不能挪用。
- 多行原料统一确认，有一行不足时整张单不扣库存、不产生库存流水。
- 确认成功后，原系统「其他出库」出现关联单据，领料单状态为已领料出库。
- 重复点击不会重复扣库存。

库存不足时等待原料采购入库后再确认，或退回主任说明原因，主任调整后重新提交。本模块不自动发起采购审批或付款，也不因领料单已确认就自动宣布可以开工。

## 补料

主任选择同一生产任务，点击「开补料单」，填写产品、工序、车间及原料明细，补料原因必填。后续提交和仓库确认与领料一致。补料单独编号、保留记录，不覆盖原领料数量。

## 退料

1. 主任选中一张已确认的领料或补料单，点击「关联退料」。
2. 系统带出原料、原批号和扣除已确认退料后的可退数量。
3. 可以部分退回，填写本次数量、收料仓库及退料原因；不能改成其他原料或其他批号。
4. 保存、提交后，由仓库收到实物再点击确认。
5. 确认后生成原系统「其他入库」，恢复实物库存。累计已确认退料不能超过原单已领数量，并发操作也会重新核对。

一张退料单对应一张原领料或补料单；不同原单分别退料。退料入库不会自动获得成品质检合格或领导放行资格。

## 修改与关联保护

- 草稿、已退回单据由主任修改；待仓库确认的单据可先撤回修改或撤销。
- 仓库可以填写原因退回待确认单据。
- 已确认单据不能直接修改、撤销或反审核。多领原料另开退料单，实际退料和仓库交接均留记录。
- 原「其他入库/其他出库」页面可以查看库存流水，但不能直接删除、修改、反审核本模块生成的关联流水。
- 已存在有效领补退料单的产品、工序、车间安排不能直接移除；人员、班次等安排仍可在保留原关联工序的情况下调整。
- 开单、修改、提交、仓库确认、退回和撤销均留记录，并同步到生产联系表操作记录中。

## 当前范围

完成领料、补料、退料及仓库库存联动。实际开工、原料齐套确认、生产日报、实际耗用和损耗、半成品送检与流转、成品入库在后续模块接入。本次不自动扣生产损耗，也不自动增加成品库存。

## 后续开发接入

实物库存只写原jsh_depot_head/jsh_depot_item，领补退料表保存任务关系、申请和确认状态、关联库存头id，不另存实物库存。确认在同一事务中校验数量、生成库存流水和更新状态；事务使用READ_COMMITTED并取得既有租户库存排他锁，避免等待后读旧快照。库存锁由INSERT ON DUPLICATE KEY UPDATE直接取得排他锁，避免先共享再升级造成死锁。

本机升级顺序为002至006，再部署当前后端。生产联系表服务、库存流水保护都会读取006新增表，因此不可只部署代码而遗漏迁移。

后续开工模块需由主任核对原料齐套，结合未确认领料单和实际到料情况处理，不应仅凭存在一张已发料单自动开工。日报、实际耗用和损耗继续关联生产task_head_id、产品line_no、stage_no及workshop_no。任务完成后退料或更改单据规则需在引入完成状态时接入，不能绕过已确认流水保护。


## 三车间主任权限更新

生产统筹负责分配路线；三个车间分别由对应主任开立和处理本车间领补退料单。主任不能修改或提交其他车间的单据。仓库确认权限仍独立，可统一处理各车间申请。

只检查本次领料车间是否完成排班，不要求整张联系表的全部车间都已排班。旧排班在升级后须由对应主任接单并核对保存。当前后端部署需在006之后执行007_workshop_directors.sql。
