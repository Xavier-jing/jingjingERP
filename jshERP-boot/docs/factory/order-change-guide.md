# 生产中订单变更与取消

入口：「销售管理 → 生产中订单变更与取消」，也可从销售订单工具栏进入。适用于已审核、车间已完成排班的生产订单。

## 配置与流程

租户负责人配置多位实际变更审批领导，任意一位批准即可。销售、领导、生产统筹需配置相应菜单。统筹身份复用生产人员配置。

1. 原订单销售选择本人生产中的订单，申请数量、交期、客户要求变更，或申请整单取消；原因必填。产品、规格、单价、客户和付款条件沿用原单，需要变更这些内容时另开订单。
2. 同一订单同时只允许一份待处理申请。待领导审批时仍按原计划生产；领导可说明原因退回，销售可说明原因撤回后重新申请。
3. 任意一位配置领导批准后，显示「待统筹落实」。此时暂缓新增生产和领补料，等待统筹核对最新进度。现有产出的质检、流转、入库及退料可继续处理。批准本身不会覆盖订单和计划。
4. 生产统筹打开申请，查看变更前后内容、最新日报产量和原排班。逐行填写调整后的**累计计划量（包含已经生产的数量）**，并说明调整或停产安排。相同产品、工序、车间的排班合计不能低于实际已记录产出。
5. 统筹落实时在一个事务中更新订单数量、交期、客户要求和金额；价格沿用原单，由服务器重算金额。同时释放该订单原预留和库存核查，仓库需重新核查、按新需求预留。
6. 现有产品行、工序、车间、排班人员与日期及实际开工保留，本次调整累计计划数量；变更前后排班和路线完整留档。为保留已在制或多余产出，各工序累计计划可不同，也可高于新订单需求，须在统筹说明中记录处置。新增产品、路线或车间属于另行安排，不在本模块修改范围。

## 整单取消

统筹确认取消时，订单标记「已取消」，原订单数量和金额作为历史内容保留；各现有产品工序车间计划收至实际已记录产量，停止新增生产和领补料。已确认单据不删除，不回滚真实生产和库存。

已经领出的原料仍可关联原领料单办理退料；已生产半成品、成品仍可完成原质检、流转、成品入库和领导放行。多余合格库存可由其他订单正常预留、发货。取消不自动报废、不自动退料，也不自动处理外部财务。

## 发货及记录

- 已有发货申请须先由销售撤销；已确认出库不能变更或取消，客户退货走独立退货模块。
- 待审或待统筹落实的变更会阻止新发货申请，避免在处理期间按旧条件出库。
- 统筹落实时重新核对订单、预留和生产版本；页面打开后若发生变化，需刷新后重新核对。并发落实只允许一次成功。
- 详情保留订单变更前后数量、交期、客户要求、原因、各环节人员和时间，以及统筹落实前后排班。销售订单和生产任务记录也可追踪变更。
- 减量不抹除已生产数量；整单取消不会把历史数量改为零，也不会继续显示待生产缺口。

## 部署与检查

迁移 `016_order_changes.sql` 在前序工厂迁移之后执行一次。本机备份：忽略目录 `.quality-local/before-order-changes.sql`。

`tests/factory_order_change_workflow.py` 使用临时订单和生产任务验证审批、原计划继续、统筹调整、价格与金额、版本、并发取消、真实退料及取消后成品供其他订单使用。结束后清理临时数据并恢复配置。可加 `--preview` 检查页面，回车后清理。
