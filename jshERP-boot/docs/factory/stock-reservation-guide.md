# 仓库订单库存核查与预留

## 如何使用

1. 刷新 ERP；如侧栏未出现新菜单，退出后重新登录。
2. 打开「仓库管理 → 订单库存核查」。领导审核通过的销售订单会自动出现。
3. 选中订单，点击上方「库存核查与预留」。核查界面默认全屏。
4. 查看客户要求、产品牌号规格、批次库存和检测报告，手动填写各仓库、各批次的预留吨数。
5. 勾选已核对，点击「确认预留并更新缺口」。销售在订单详情的库存信息中直接查看结果，刷新可读取最新结果。
6. 后续需要调整时重新打开修改；「释放预留」可释放整单。每次确认、调整和释放均留记录。

## 已实现的业务规则

- 缺口 = 订单需求量 − 已确认预留量。仅有库存、没有确认预留时，仍计入缺口。
- 同一产品可以分不同仓库、不同批次预留；不能超过产品行需求或批次合格可用量。
- 合格但待领导放行的在库产品允许预留，页面明确提示尚未放行。
- 未登记质检、待检、不合格和退货待处理的数量不能预留；退货经高层确认允许重售后才计入合格可预留量。
- 预留占用可用量，不扣实物库存；多个订单不能重复占用同一份库存。
- 仓管可以修改和释放预留，销售撤回订单时自动释放。
- 原有入出库、审核及删除操作如果会使合格库存低于已预留量，整次操作会回滚并提示先调整预留。
- 预留调整不会自动修改生产任务；销售需与车间协调。

## 后续模块接入约定

实物来源仍是原系统入出库明细；预留表只保存占用关系，不另存实物库存。质量投影 jsh_factory_batch_quality 以原入库明细 item_id 关联，记录合格量、质检状态、放行状态及退货重售确认。后续质检/退货模块更新质量状态时，必须在同一事务先调用 FactoryStockService.lockForInventoryMutation，再更新投影；若减少可用合格量导致预留失效，须先协调调整预留。不得通过仓库预留接口填写质检结论。

实际出库接入时，同一事务内校验领导放行、消耗对应订单预留、写原出库明细；不能全局关闭预留保护。无批号的历史库存需要补充可追溯入库批次和质检数据后使用。

## 查询区调整

查询布局沿用「其他出库」：首行是单据编号、商品信息、单据日期，以及查询、重置、展开/收起。展开后显示客户、预留仓库、操作员、核查状态和单据备注。

单据日期按销售订单创建日期筛选；默认近三个月，重置会清空其他条件并恢复这个日期范围。预留仓库指订单已确认预留的仓库，未预留的订单不匹配该条件。操作员指销售订单创建人。查询条件组合生效后再分页。
